## 2. QC20 实时读数动态模拟

使用真实 `QC20Ballbar`、`BallbarReading`、单位对象和
`QC20BallbarDevice.get_LatestReading()`。

```text
设备值              12.5
原版 PrimaryQuantity 12.5
原版 DisplayQuantity 12.5
修改 PrimaryQuantity  6.25
修改 DisplayQuantity  6.25
```

结论：实时 getter 对位移/偏差源值严格输出 50%，单位转换对象正常工作。
该测试没有把标称长度或校准偏置加入显示公式，因此不能外推为每种显示模式下
最终屏幕上的整个表达式都严格减半。

独立复核再次使用 `8、-4、0.125、0` 四个实时值测试：

```text
原版输出   8, -4, 0.125, 0
修改输出   4, -2, 0.0625, 0
```

正数、负数、小数和零均符合预期。

## 4. ISO 230 核心算法

使用真实 `Iso230V2005Analysis` 对相同 360° CW/CCW 合成样本分别
输入 100% 与 50% 幅值。

| 特征 | 原值 | 50% 输入 | 比例 |
|---|---:|---:|---:|
| CW 圆度偏差 | 10.301193 | 5.150597 | 50% |
| CW 最大径向偏差 | 5.150596 | 2.575298 | 50% |
| CW 最小径向偏差 | -5.150598 | -2.575299 | 50% |
| CCW 圆度偏差 | 10.294984 | 5.147492 | 50% |
| 双向圆度偏差 | 0.090067 | 0.045034 | 50% |

最大/最小偏差的角度位置保持不变，符合幅值缩放预期。

这些结果验证的是线性偏差幅值。角度、测试半径、进给率、温度、日期、序号、
百分比、阈值判断和诊断分类不属于“应全部减半”的承诺范围。

## 6. 完整应用隔离启动

分别建立原版和最终双 DLL 修改版的独立运行副本，隐藏启动
`Renishaw Ballbar 20.exe`。

```text
原版     启动后持续运行 8 秒：通过
修改版   启动后持续运行 8 秒：通过
```

测试进程随后被关闭，实际安装目录未用于该启动测试。
封包前又对与最终包内两个修改版 DLL 哈希完全一致的运行副本重测一次，
修改版应用在 8 秒观察窗内保持运行，随后仅关闭该测试进程。

## 7. 尚需 QC20 实机确认

- 蓝牙实机连接；
- 一次完整的开始/结束采集；
- 实时界面数值和最终报告的同次测试对照；
- 目标电脑的 WDAC/AppLocker/安全软件策略；
- 物理打印机或 PDF 驱动的最终打印排版。
- 真实软件保存测试文件、关闭后重新打开的动态往返。

这些剩余项目属于硬件与目标环境验证；代码中的实时、正式采集、分析和报告
数值链已经完成动态模拟。

保存/重开虽然未完成整段动态往返，但已核对真实 XML formatter 的 IL：
`StoreBallbarRun` 将 `IRunResult.Readings` 直接按 invariant culture 和
五位小数写出，`PopulateRunResult` 经 `ParseReadingsString` 直接
`Double.TryParse` 后加入 `Readings`；两端都没有缩放，且重开链不调用
`ReadRecord()`。因此不会二次减半，只有五位小数舍入风险。独立 harness
卡在脱离应用容器时无法构造已注册 `Celsius`/`hertz` 的完整 Renishaw 单位
目录，而不是卡在 readings 的保存或解析。
