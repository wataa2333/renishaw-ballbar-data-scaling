# QC20 数据路径审计

## QC20 新测试正式结果

```text
QC20Ballbar
→ BallbarInstrument 采集缓存
→ QC20BallbarDevice.m_instrument_FeedOutDetected()
→ QC20BallbarDevice.PopulateRunResult()
→ BallbarInstrument.ReadRecord()
→ IRunResult.Readings.Add()
→ 分析 / 曲线 / 报告 / 保存
```

扫描 `Application` 和 `Simulator` 的全部可读取 .NET 程序集后，
`BallbarInstrument.ReadRecord()` 的业务调用者只有：

```text
QC10BallbarDevice.PopulateRunResult()
QC20BallbarDevice.PopulateRunResult()
```

对于只使用 QC20 的场景，正式采集读取入口只有后一处。

由于 `ReadRecord()` 同时被 QC10 使用，本正式采集补丁也会缩放未来的
QC10 正式结果；实时 getter 补丁则明确只修改 QC20。最终包只适用于 QC20，
安装后不应连接 QC10。

QC20 `CaptureAsync` 对 `IRunResult.Readings` 的直接操作是 `Clear()`；
实际添加采样只发生在 `PopulateRunResult()`。

`BallbarInstrument.CalculateIndices()` 会直接调用
`BufferingFilter.ReadBuffer()`，但它只用于计算采集起止索引，不负责写入
测试结果。本修改没有影响该路径。

## QC20 实时显示

```text
QC20Ballbar.get_LatestReading()
→ QC20BallbarDevice.get_LatestReading()
→ CaptureBallbarViewPresenter / MonitorBallbarViewPresenter
```

实时 getter 的业务消费者只有上述两个 UI Presenter。将乘法放在
`QC20BallbarDevice` 层，不会改变底层状态、采集触发或校准链。

该 getter 缩放的是进入 UI 公式前的位移/偏差源值。Monitor 界面之后仍可能
按显示模式执行其他运算：

```text
显示绝对长度：0.5 × 位移值 + 标称长度
显示未校准值：0.5 × 位移值 - 校准偏置
```

因此不能把它表述为“每种显示模式下，最终屏幕上的整个数字都严格减半”。
它在常用偏差显示模式中直接显示一半；含标称长度或校准偏置的表达式只缩放
其中的位移源值。

实时路径生成的 `Measurement` 只供 UI 使用，不会写回采集缓存或
`RunResult.Readings`。正式结果路径读取缓存时不调用实时 getter，所以两条
路径各乘一次 0.5，不会双重缩放。

## 触发、索引与校准

`ReadRecord()` 发生在录制结束和 `CalculateIndices()` 完成之后。
`CalculateIndices()` 直接读取未缩放缓冲区；FeedIn/FeedOut、起止索引及
采集触发不经过补丁。校准和设备补偿直接操作底层设备及其补偿参数，也不经过
DeviceService 的实时 getter。

这里修改的不是蓝牙协议原始字节，而是设备现有补偿/滤波后、已经进入采集
缓冲区的正式位移样本读取出口。

## 旁路数据源

以下路径不经过本修改：

```text
XmlDocumentFormatter.PopulateRunResult()   旧 XML 导入
RtbDocumentFormatter.PopulateRunResult()   旧 RTB 导入
ComRunResultAdapter.AddReading()            Legacy/COM
clsSimulationEngine                         独立模拟器
ISimulationResult.Readings                  诊断模拟曲线
```

因此不能说 `ReadRecord()` 是整个软件唯一的数据来源；可以确认它是当前版本
中 QC20 新实机测试写入正式 `RunResult.Readings` 的唯一读取入口。

修改后新保存的数据文件包含半值样本，重新打开不会经过 `ReadRecord()`，
所以不会再次减半。进一步核对 XML formatter 的 IL：

```text
保存：IRunResult.Readings → CreateReadingsString
      invariant culture，格式 +0.00000;-0.00000
读取：READINGS → ParseReadingsString → Double.TryParse → Readings.Add
```

两端均没有比例乘法；重开半值文件不会再变为 25%，只可能产生五位小数
格式化带来的舍入。本次没有完成真实软件的“保存文件→关闭→重新打开”动态
往返试验，因为脱离应用容器构造 `RunResult` 时，真实单位转换还要求已注册的
`Celsius` 和 `hertz` 完整单位目录。

## 数值语义边界

严格减半的是 QC20 位移/偏差样本以及线性的偏差幅值。角度、样本数、采样率、
进给率、测试半径、温度、日期和序号不应变化；百分比、阈值判断、诊断分类及
其他非线性派生结果也不保证为原结果的 50%。
